# آکادمی Mobile Legends Bang Bang (MLBB Academy)

این پروژه یک وب‌سایت آموزشی برای بازی Mobile Legends Bang Bang است که با PHP خام پیاده‌سازی شده و APIهای استاندارد JSON را برای مصرف در اپلیکیشن‌های موبایل (مانند Flutter) فراهم می‌کند. تمرکز فعلی روی مدیریت هیروها، آیتم‌ها و سناریوهای کانتر است.

## امکانات کلیدی

- دیتابیس کامل برای هیروها، مهارت‌ها، کامبوها، قدم‌های اجرای کمبو، نکات، کانترهای گروه‌بندی‌شده، نقاط قوت و ضعف
- مدل جامع آیتم‌ها براساس دسته‌بندی‌های Attack، Magic، Defense، Movement، Jungle و Roam همراه با متادیتای کامل
- API عمومی بازنویسی شده برای لیست و جزئیات هیروها و آیتم‌ها با پشتیبانی از فیلتر، مرتب‌سازی و صفحه‌بندی
- صفحه اصلی و صفحه اختصاصی آیتم با بارگذاری تصویر مستقیم از دیتابیس (بدون نیاز به مسیر ثابت)
- پنل مدیریت با ناوبری کارت‌محور، فیلتر حرفه‌ای هیروها، و فرم‌های ماژولار برای مدیریت داده‌ها و آپلود تصویر
- اسکریپت Seed برای درج کامل هیرو Gloo به‌همراه گروه‌های کانتر و آیتم‌های پیشنهادی

## پیش‌نیازها

- PHP 8.1 یا بالاتر با فعال بودن PDO و PDO MySQL
- MySQL 5.7 یا بالاتر / MariaDB
- وب‌سرور (Apache یا Nginx)
- Composer برای مدیریت فونت فارسی (اختیاری)

## راه‌اندازی قدم‌به‌قدم روی هاست

1. **ایجاد دیتابیس**
   - یک دیتابیس جدید با نام دلخواه (مثلاً `mlbb_academy`) در MySQL ایجاد کنید.
   - کاربر دیتابیس را با دسترسی کامل به این دیتابیس تنظیم کنید.

2. **بارگذاری فایل‌ها روی هاست**
   - کل مخزن پروژه (همین ساختار فعلی) را داخل `public_html` یا روت سرویس‌دهی وب‌سرور خود آپلود کنید.
   - فایل `.htaccess` موجود در ریشه، تمام درخواست‌ها را به پوشه `public/` هدایت می‌کند؛ بنابراین نیاز نیست محتویات را جابه‌جا کنید.
   - اگر پس از آپلود با خطای 403 مواجه شدید، مطمئن شوید که همین فایل `.htaccess` در ریشه وجود دارد تا با دستور `DirectoryIndex`، صفحه `public/index.php` به عنوان صفحه اصلی بارگذاری شود.
   - اگر ساختار متفاوتی روی هاست دارید، فقط مطمئن شوید که فایل `.htaccess` در همان مسیری قرار بگیرد که درخواست‌های وب وارد آن می‌شوند.

3. **تنظیمات اتصال دیتابیس**
   - فایل `config/config.php` را باز کرده و فقط مقادیر `DB_HOST`, `DB_DATABASE`, `DB_USERNAME`, `DB_PASSWORD` را متناسب با هاست خود تنظیم کنید یا همین مقادیر را در فایل `.env` قرار دهید.
   - نام کاربری مدیر را از کلید `ADMIN_USERNAME` مشخص کنید و برای رمز عبور از مقدار هش‌شده `ADMIN_PASSWORD_HASH` استفاده کنید. برای ساخت هش می‌توانید در خط فرمان دستور زیر را اجرا کرده و خروجی را در فایل `.env` قرار دهید:

     ```bash
     php -r "echo password_hash('رمز-دلخواه-شما', PASSWORD_DEFAULT), PHP_EOL;"
     ```

4. **ساخت جداول**
   - فایل `database/schema.sql` را در phpMyAdmin یا با ابزار خط فرمان روی دیتابیس اجرا کنید تا تمام جداول ساخته شوند.
   - سپس `database/seed_roles.sql` را اجرا کنید تا جدول نقش‌ها مقداردهی اولیه شود.

5. **بارگذاری دیتا نمونه (اختیاری)**
   - اگر دسترسی CLI دارید، دستور زیر را در روت پروژه اجرا کنید تا هیرو Gloo با تمام اطلاعاتش اضافه شود:
     ```bash
     php scripts/seed_gloo.php
     ```
   - در غیر این صورت محتویات فایل `scripts/seed_gloo.php` را در یک تب جدید در هاست خود اجرا کنید یا داده‌ها را به صورت دستی در پنل مدیریت وارد کنید.

6. **تنظیم ساختار URL**
   - فایل `.htaccess` موجود در ریشه به‌طور خودکار درخواست‌هایی مانند `/admin/index.php` یا `/assets/...` را به پوشه `public/` هدایت می‌کند و هم‌زمان دسترسی مستقیم به پوشه‌های حساس (`config`, `database`, `scripts`) را مسدود می‌سازد.
   - اگر وب‌سرور شما از `mod_rewrite` پشتیبانی نمی‌کند، باید فایل‌ها را به صورت دستی در مسیر سرویس‌دهی قرار دهید یا قوانین مشابهی را در وب‌سرور خود پیاده‌سازی کنید.

7. **بررسی دسترسی پنل مدیریت**
   - به آدرس `https://your-domain.com/admin/login.php` بروید.
   - با اطلاعاتی که در مرحله 3 تنظیم کرده‌اید وارد شوید.
   - از اینجا می‌توانید هیرو، مهارت، کامبو، نکته، کانتر و نقاط قوت/ضعف را اضافه کنید.

8. **تأمین فایل‌های تصویری**
   - تمام تصاویر هیرو، مهارت، آیتم و کانتر را یک‌بار در مسیر `public/assets/uploads/...` قرار دهید (به‌صورت پیش‌فرض زیرپوشه‌های `heroes`, `skills`, `items` ساخته می‌شود).
   - در فرم‌های پنل مدیریت تنها کافی است مسیر نسبی مانند `/assets/uploads/items/dominance_ice.png` ذخیره شود؛ چه در وب‌سایت و چه در API‌ها همان مسیر به شکل صحیح (`/mlbb/public/...`) خروجی داده می‌شود و نیازی به اصلاح دستی نیست.

## API ها

APIها هیچ احراز هویت خاصی ندارند و به‌صورت JSON پاسخ می‌دهند. همهٔ پاسخ‌ها شکل کلی زیر را دارند:

```json
{
  "status": "success",
  "data": {},
  "meta": {}
}
```

- در صورت خطا `status` برابر `error` است و کلید `message` دلیل خطا را توضیح می‌دهد.
- آدرس پایهٔ API نسبت به روت `public` است؛ برای نمونه `https://example.com/mlbb/public/api/heroes.php`.

### لیست هیروها — `GET /api/heroes.php`

پارامترهای قابل استفاده:

| نام | نوع | توضیح |
| --- | --- | --- |
| `page` | عدد | شماره صفحه (پیش‌فرض ۱) |
| `per_page` | عدد | آیتم در هر صفحه (۵ تا ۱۰۰) |
| `search` | رشته | جستجوی نام فارسی یا انگلیسی |
| `role_id` | عدد | فیلتر بر اساس نقش |
| `sort` | مقدار `name`، `recent`، `oldest` | ترتیب نمایش |
| `include` | `stats` | با مقداردهی `stats`، تعداد مهارت/کامبو/نکته/کانتر برای هر هیرو برگردانده می‌شود. |

نمونه درخواست: `GET /api/heroes.php?search=gloo&include=stats`

نمونه پاسخ خلاصه‌شده:

```json
{
  "status": "success",
  "data": [
    {
      "id": 1,
      "name_fa": "گلو",
      "role": {
        "name_fa": "تانک"
      },
      "image_url": "/mlbb/public/assets/uploads/heroes/gloo.png",
      "metrics": {
        "skills": 4,
        "combos": 3,
        "tips": 8,
        "counter_groups": 6
      }
    }
  ],
  "meta": {
    "total": 1,
    "page": 1,
    "per_page": 20,
    "filters": {
      "search": "gloo",
      "include": ["stats"]
    }
  }
}
```

### جزئیات هیرو — `GET /api/hero_detail.php?id={HERO_ID}`

برمی‌گرداند:

- اطلاعات کامل هیرو (مشخصات، ویژگی‌ها، لینک صفحه عمومی و API)
- لیست مهارت‌ها به همراه تصویر و نوع آسیب
- کامبوها و قدم‌های مصور هر کامبو
- نکات و ترفندها با اولویت‌بندی
- گروه‌های کانتر (هیروها و آیتم‌ها) با لینک مستقیم به صفحهٔ مربوط
- نقاط قوت و ضعف

### لیست آیتم‌ها — `GET /api/items.php`

پارامترها:

| نام | نوع | توضیح |
| --- | --- | --- |
| `category_id` | عدد | محدود کردن نتایج به یک دستهٔ خاص |
| `search` | رشته | جستجوی نام |
| `sort` | `name`، `price_desc`، `price_asc` | ترتیب نمایش |
| `page` / `per_page` | عدد | صفحه‌بندی (۶ تا ۱۰۰ مورد در هر صفحه) |

هر آیتم شامل نام فارسی/انگلیسی، قیمت طلا، تصویر و اطلاعات دسته‌بندی است.

### جزئیات آیتم — `GET /api/item.php?id={ITEM_ID}` یا `GET /api/item.php?slug=sea-halberd`

برگشت می‌دهد:

- اطلاعات کامل آیتم (ویژگی‌ها، پسیو، اکتیو، توضیحات، تصویر)
- دسته‌بندی و لینک‌های دسترسی وب/API
- لیست هیروهایی که این آیتم را در کانترها پیشنهاد داده‌اند به همراه عنوان گروه کانتر

## ساختار پوشه‌ها

```
config/
  ├── config.php          // تنظیمات عمومی پروژه
  └── database.php        // کلاس اتصال به دیتابیس

public/
  ├── index.php           // صفحه اصلی نمایش هیرو
  ├── assets/css/styles.css
  ├── api/
  │     ├── bootstrap.php // توابع مشترک API
  │     ├── heroes.php    // API لیست هیروها
  │     ├── hero_detail.php
  │     ├── items.php     // API لیست آیتم‌ها
  │     └── item.php      // API جزئیات آیتم
  └── admin/
        ├── index.php     // پنل مدیریت
        ├── login.php
        └── logout.php

database/
  ├── schema.sql          // ساخت جداول
  └── seed_roles.sql      // داده اولیه نقش‌ها

scripts/
  └── seed_gloo.php       // درج هیرو نمونه Gloo
```

## نکات امنیتی پیشنهادی

- حتماً رمز عبور پنل مدیریت را تغییر دهید و آن را در فایل‌های نسخه‌ساز نگه ندارید.
- برای محیط‌های پروداکشن از HTTPS استفاده کنید.
- دسترسی پوشه‌های `config`, `database`, `scripts` را از وب مسدود کنید.
- در صورت نیاز احراز هویت پیشرفته‌تر (JWT، نقش‌ها، مدیریت کاربران) را اضافه کنید.

## برنامه ادامه (درخواست کارفرما)

- افزودن API‌های بیشتر (بیلدها، آیتم‌ها، اخبار)
- آماده‌سازی خروجی JSON بهینه برای استفاده مستقیم در اپلیکیشن Flutter
- پیاده‌سازی مدیریت فایل (آپلود تصویر) در پنل مدیریت
- چندزبانه کردن کامل پنل مدیریت

> **یادآوری:** فعلاً بخش Flutter نادیده گرفته شده است و روی وب‌سایت تمرکز شده است. در ادامه می‌توان APIها را به فرمت و ساختار مناسب برای اپ موبایل گسترش داد.
